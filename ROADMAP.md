# Roadmap — what is still missing

Companion to [CONSOLE_V2_SPEC.md](CONSOLE_V2_SPEC.md). The spec says what the console is;
this says what it is not yet, measured against the code and the running emulator rather
than against ambition. Every claim carries a `file:line` you can open.

Status legend: ✅ shipped · 🚧 shipped but thin · 🧭 planned · ❌ will not happen (and why).

met for 3.2% of the served services and 0.6% of the served operations. That is the headline
gap, and it is what M1 attacks.

## M1 — Close the coverage gap (the one that matters)

Today, a service the emulator answers but that has no driver gets a read-only focus panel and
no way to act: [src/views/detail.rs:1251](src/views/detail.rs#L1251) returns `None` from
`render_operations` unless `is_managed(service)`. 327 services are in that position.

Three ways out, and they are not all compatible:

- 🧭 **A. Prioritised drivers (recommended first step).** Add Tier A drivers for the served
  services a local emulator user actually reaches for. [SERVICES.md](SERVICES.md) is the full
  per-service list; the curated shortlist is below, and note that it is *not* the raw
  operations ranking — the raw one is led by `glue` 306, `quicksight` 299 and `iot` 272, which
  nobody provisions on a laptop. So: `ssm` 152 · `config` 102 · `networkmanager` 95 ·
  `workspaces` 91 · `cloudformation` 90 · `elasticache` 77 · `route53` 71 · `athena` 70 ·
  `autoscaling` 68 · `cloudtrail` 60 · `codebuild` 59 · `ecr` 58 · `events` 57 · `kms` 54 ·
  `elasticloadbalancing` 51. Each is one crate in `Cargo.toml` + one `src/aws/drivers/*.rs` +
  one `MANAGED` entry + rows in `operations.rs` — the pattern is proven 11 times over.
  Ten of these is roughly the same work as the eleven already done.
- 🧭 **B. Generic operation runner.** One page that calls *any* operation of *any* served
  service. This is the only thing that can satisfy the scope rule for all 338 at once, and it
  has a hard obstacle: the AWS SDK is per-service, so a runner still needs the `aws-sdk-*`
  crate on the dependency graph — 327 of them is not a buildable idea. The alternative is
  hand-building Smithy HTTP requests, which breaks the standing rule *"dont implement the sdk
  yourself, use aws rust sdk"*. **Decision needed — Q1.**
- 🧭 **C. Honest escape hatch (cheap, ship alongside A).** The focus panel for an unmanaged
  service already says what is missing ([src/views/catalog.rs:353](src/views/catalog.rs#L353)).
  Add a copyable `aws --endpoint-url https://127.0.0.1:9297 <service> <op>` snippet built from
  the catalog's own `signingName`/`version`, so the console tells you exactly how to do the
  thing it cannot do. This is the only option that costs hours and covers all 338.

**Done means:** for option A, each new service lists live resources, offers create/delete, and
its operations table is generated from the driver's real coverage; for C, every unmanaged
service page shows a snippet that runs.

## M2 — Things that are wrong today (small, high-value)

- 🧭 **The one-time secret cannot be copied.** The reveal banner is a plain `div`
  ([src/views/detail.rs:1690](src/views/detail.rs#L1690)) with a Dismiss chip and no Copy
  button, and GPUI does not select text out of a div. The clipboard machinery exists but only
  inside the text field ([src/views/text_field.rs:201](src/views/text_field.rs#L201)). Today a
  user reads a secret key off the screen and retypes it. Needs a Copy button that writes to the
  clipboard and never to a file.
- 🧭 **Control panel contradicts itself.** A green `Running` pill sits beside the words
  "not started" ([src/views/control_panel.rs:122-135](src/views/control_panel.rs#L122)): the
  pill comes from the health probe, the words from `startup.backend`, which is only set when
  *this* dashboard started the process. Wording should say "reached, not started here".
- 🧭 **No `Escape` anywhere.** The only app-level action is `RefreshAll`
  ([src/views/root.rs:18](src/views/root.rs#L18)). A dialog closes only by clicking Cancel, and
  there is no keyboard path into the tables or the nav.
- 🧭 **Traffic log is a list, not a tool.** `TrafficEntry` carries
  `at/method/path/status/latency_ms` only
  ([src/emulator/proxy.rs:19-25](src/emulator/proxy.rs#L19)); there is no filter (the one
  `input_filter` field belongs to Instances, [src/app_state.rs:158](src/app_state.rs#L158)), no
  per-request detail, no export, no pause, and the view truncates silently at `MAX_ENTRIES`
  ([src/views/traffic_log.rs:195](src/views/traffic_log.rs#L195)).
  *Guardrail while adding detail:* headers must stay out of the log, or `Authorization` has to
  be redacted before it is stored — nothing does that today because nothing stores headers.
- 🧭 **Grid view's "+N more" is a dead end.** [src/views/catalog.rs:265](src/views/catalog.rs#L265)
  tells the user to switch to list view instead of doing anything. Make it a link that switches
  the view and opens that group.

**Done means:** each of the five is testable — a clipboard test for the copy, a render test for
the wording, an action test for `Escape`, a filter/export test for traffic, and a click-through
test for the group link.

## M3 — Depth inside the 11 managed services

🚧 The pages exist; their operation coverage is the thin part. 78 buttons against 1,631
operations in the same services.

- 🧭 **Per-service capability panel from real evidence.** Each driver already reports which
  operations answer and which the emulator refuses; those tables should drive a panel that
  marks each operation ✅ works / 🧭 scaffolded / ❌ refused, with the emulator's own error
  string. Spec "Honest gaps" #2 promises exactly this and it is not built.
- 🧭 **EC2 first.** 4 of 807. The obvious next tranche: security groups, key pairs, VPC
  sub-resources, volumes, and instance-type listing — the things you point an emulator at.
- 🧭 **S3 next.** 112 operations, and the page today is bucket list + object list + upload /
  download / delete. Missing: versioning, ACL/grants, tags, lifecycle, presigned URL display
  (the emulator's `url_signer` output is the interesting part of a local emulator).
- 🧭 **IAM.** 180 operations; the page lists users and keys. Roles are an operation button, not
  a managed resource; policies and attachments are absent.
- 🧭 **CloudWatch (`monitoring`).** 55 operations, no `create_action` entry
  ([src/views/catalog.rs:30](src/views/catalog.rs#L30)) — alarms can be read and deleted but not
  made. Overview "Alerts" has no severity model (spec "Honest gaps" #5).

## M4 — Scale, input, and state

- 🧭 **Virtualise the long tables.** List view renders every row of every group
  ([src/views/catalog.rs:171](src/views/catalog.rs#L171)) — 338 rows plus headers on one scroll
  surface; resource tables and traffic do the same at whatever size the emulator grows. Needs a
  windowed list before someone lists a big bucket.
- 🧭 **Real service icons.** Zero assets are registered ([src/main.rs](src/main.rs)), so every
  tile is a two-letter monogram in the running app, not just in screenshots
  ([src/views/root.rs:625](src/views/root.rs#L625)). Note `CloudWatch Logs` and `CloudWatch`
  both collapse to `CL` — the collision is visible today.
- 🧭 **Keyboard navigation.** Focus traversal for nav, tables and dialogs; `⌘R` refresh; `/` to
  search. Only `RefreshAll` exists.
- 🧭 **Persist UI state.** `open_groups`, `selected_service` and the last page reset every
  launch; only the eight `Settings` keys survive
  ([src/settings.rs:8-16](src/settings.rs#L8)).
- 🧭 **Settings with holes.** The options card edits port, auth, telemetry and idle timeout;
  `emulator_binary`, `poll_interval_ms` and `proxy_port` have no UI at all, so they are
  edit-the-file keys. `proxy_enabled` is only reachable by pressing Start/Stop.
- 🧭 **Region is a constant.** `pub const REGION: &str = "us-east-1"`
  ([src/aws/client.rs:8](src/aws/client.rs#L8)) is baked into every client and every subtitle.
  Correct for today's emulator; wrong the moment it serves another region.

## M5 — Reliability and distribution

- 🧭 **Error classification and retry.** Failures surface as formatted strings
  (`set_error` in [src/views/detail.rs:301](src/views/detail.rs#L301)). A scaffolded-501 from the
  emulator, a TLS/certificate problem, and a real `AccessDenied` all look alike. Needs a small
  taxonomy and, where it helps, one retry.
- 🧭 **Cancel an in-flight call.** `run` spawns and detaches
  ([src/views/detail.rs:249](src/views/detail.rs#L249)); a hung request keeps its spinner until
  it returns, and there is no way to stop it.
- 🧭 **Diagnostics.** `tracing_subscriber` writes to stdout with an env filter
  ([src/main.rs:19](src/main.rs#L19)) and nothing else, so a bug report has no artifact. Needs a
  log file under the config dir and a "reveal diagnostics" affordance.
- ✅ **Linux CI is green, and it took four pushes to find out why.** Three causes were stacked
  behind each other, and the first two were diagnosed wrongly before the log said otherwise.
  (1) `cargo clippy --all-targets` failed on `ubuntu-latest` with `E0433: cannot find
  AppleTextSystem in gpui_apple` — the render module reached for CoreText on a platform with no
  such crate; fixed by gating the module ([src/main.rs:7](src/main.rs#L7)) and then the whole
  GPUI test-support dependency block ([Cargo.toml:43](Cargo.toml#L43)) to macOS. (2) `cargo test`
  then died in the link with `linking with cc failed` and no cause, because rustc reports a
  failed link as one ~64KB `cc` line that Actions drops. The dev packages added on this theory —
  Mesa, Vulkan, EGL, GBM, DRM — bought nothing: a per-library probe showed all twenty `-l` flags
  already resolved. The gate added in (1) did not stop the crash either. (3) The real answer was
  in the filtered log: **rust-lld itself crashed** with `collect2: fatal error: ld terminated
  with signal 7 [Bus error]`, only on the test target, after `cargo build` had linked the same
  graph on the same disk — runner disk exhaustion, which is GitHub's triage for this exact
  signature ([actions/runner-images#13367](https://github.com/actions/runner-images/issues/13367)).
  The runner starts with 15G free and `target/` reaches 12G, so the job now removes the .NET,
  Android, GHC and CodeQL payloads the image ships and links with 37G free
  ([.github/workflows/ci.yml:21](.github/workflows/ci.yml#L21)). Verified on `a2fc867`: macOS 25
  passed / 25 ignored, Linux 14 passed / 23 ignored. Worth keeping in mind for the release job,
  which will want `--release` objects that do not share this `target/`.
  🧭 Still owed: those 11 pages render on one OS only, so the layout proof has a single point of
  failure until a headless text system that works on Linux is wired in.
- 🧭 **CI does not test the thing it ships.** [ci.yml](.github/workflows/ci.yml) runs
  fmt/clippy/build/test on macOS and Linux, but the 25 `#[ignore]`d live tests never run there
  because no job starts an emulator container. Either add a service-container job or state in
  the README that live coverage is local-only.
- 🧭 **No interaction-level tests at all.** The `test-support` workaround in
  [Cargo.toml:40](Cargo.toml#L40) means gpui-kit's `find`/`click`/`texts` are unavailable, so
  every UI test is a screenshot plus a state assertion. No test has ever pressed a button.
  Worth an upstream check before building a bespoke harness.
- 🧭 **Release path.** No `--release` job, no artifact upload, no `.app` bundle, no icon, no
  signing or notarization, so distributing means asking users to have a Rust toolchain.
- 🧭 **Supply chain.** 940 packages in `Cargo.lock` (11 AWS SDKs plus GPUI and its platform
  stack) with no `cargo-deny`/`cargo-audit` gate in CI.
- 🧭 **Windows.** CI matrix is `[macos-latest, ubuntu-latest]`; GPUI on Windows is untested here,
  so the README should say what is actually supported until someone proves otherwise.

## Explicitly out of scope

- ❌ **Modifying the emulator.** `/Users/snapp/projects/aws-emulator` is read-only for this
  project, and its container is never rebuilt or restarted — including by the two live tests
  that would do it (`live_manager_start_stop`, `live_proxy_signature_matrix`).
- ❌ **Faked metrics.** Metrics the emulator cannot supply stay marked unavailable
  (`theme::unavailable()`), never invented — the CPU column on Instances is the standing
  example.
- ❌ **Hand-rolled request signing.** The AWS SDKs do the calling; a generic runner that builds
  Smithy requests by hand is rejected on those grounds even though it would raise coverage.
- ❌ **Persisting a secret.** One-time credentials go to `detail.revealed` and to the
  clipboard, and to nothing else — no file, no log, no test output.
